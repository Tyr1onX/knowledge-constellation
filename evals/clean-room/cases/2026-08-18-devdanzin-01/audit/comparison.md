## Cross-layer contract gap exposed by the run

The accepted Personal Universe product baseline includes **Project Anchor** and **Identity Presence**, but the current Pass D / `visual.schema.json` does not carry Project Anchors or identity-intro semantics. Pass C produces real Anchors, then Pass D cannot preserve them into the Visual Model.

That means a clean-room end-to-end run can produce correct Recognition yet still fail to reproduce the accepted personalized product surface without an out-of-band hand-written Scene step.

This is not a devdanzin Recognition error. It is an **architecture/contract gap** exposed by the clean-room test and should be fixed before claiming v0.1 end-to-end generation.

## Recommended rule changes

1. Separate **human-verified behavior** from **AI-assisted reduction/drafting** at node-label level, not only inside hidden boundaries.
2. Allow cross-cutting concepts such as AI-assisted workflow or broad personal goal to remain motifs/secondary structure instead of forcing them into an artificial Galaxy.
3. Require `trajectory` relations to cite actual temporal evidence (first/last occurrence, ordered events, or explicit migration).
4. Wire Pass C Anchors into the Visual Model / Scene contract so Personal Universe features are generated by the Skill pipeline, not manually reintroduced later.
