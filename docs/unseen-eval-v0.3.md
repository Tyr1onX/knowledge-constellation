# Unseen-style Evaluation v0.3

The evaluation strategy does not require an exact subjective gold model for a stranger. Instead it checks bounded errors that can be audited from public material.

## Cases

### Matthew-w56 — Tauri + Java backend proof-of-concept

Expected guard: the source explicitly avoids using the project as a time to learn Rust, so the system must not manufacture strong Rust capability. The accepted structure forms one project-centered Galaxy around Tauri / Java backend integration.

### Rakshitha-D — current React learner

Expected guard: `currently learning React` must remain a developing learning state rather than established capability. A small collection of JavaScript/front-end exercises may form a learning/practice theme, but an isolated sign-language notebook must not automatically become a machine-learning capability Galaxy.

### hethon / ATFS — Android tooling learning journey

Expected guard: detailed tooling study must not become broad professional Android mastery. An Android Studio chapter marked not-yet-published must not appear as completed learning.

### Oli Treadwell — public professional resume

Expected guard: recurring professional themes may be recognized from a detailed self-authored resume, but the system must not invent external validation from that same source. Strong independence/implementation claims still require the validator's independent-evidence gate.

## Result

All four current bounded guards pass. The four cases produce different Galaxy counts and multiple global visual composition archetypes, which is an early signal that Personal Visual Model output is responding to Recognition structure instead of merely renaming a fixed template.

This remains an engineering evaluation, not a universal human-recognition accuracy score. Truth Calibration and Identity Calibration remain necessary when important facts or subjective representativeness are not observable from public evidence.
