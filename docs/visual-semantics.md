# Visual Semantics｜视觉语义契约

> 目标不是先设计“好看的星图”，而是先保证每一种视觉变化都不会悄悄改变知识模型的含义。

Knowledge Constellation 最大的视觉风险之一是：

> **用户会自然把“大、亮、中心”理解成“很强”。**

但我们的模型已经明确区分：

- 代表性；
- 证据置信度；
- 解析度；
- 能力状态；
- 近期性；
- 结构关系。

因此视觉层不能重新把这些维度压回一个“强弱值”。

---

## 1. Visual Semantics Contract｜视觉语义契约

V0 的基本要求：

> **一个主要视觉通道尽量只表达一个主要含义。**

不要让“星星大小”同时受：

- 能力；
- 活跃度；
- 证据量；
- 用户偏好；
- 项目数量；

共同控制。

否则用户无法知道它为什么大，系统自己也无法解释。

---

## 2. Overview 层不直接表达单一能力等级

第一眼的 Universe Overview 主要回答：

1. 哪些部分最能代表这个人；
2. 它们如何组成几个个人主题；
3. 哪些地方看得清，哪些仍然模糊；
4. 哪些区域最近正在形成或活跃。

它不需要精确回答：

> “这个人的 Rust 到底是 2.7 级还是 3.1 级？”

具体能力状态可以在 Hover / Focus / Detail 层再展示。

这样可以显著降低：

```text
大星 = 熟练
亮星 = 专家
中心 = 最强技能
```

这类错误直觉。

---

## 3. 建议的视觉变量分工

这些映射目前是研究方向，不是最终美术规范。

### 3.1 Size / Presence｜视觉存在感

主要表达：

> `representativeness`｜这个节点有多能解释“现在这个人是谁”。

来源可能包括：

- 多次重复；
- 多 Anchor 关联；
- 持续性；
- 结构解释力；
- Identity Calibration 后的个人重要性。

它**不直接表达 proficiency**。

### 3.2 Position / Distance｜位置与距离

主要表达：

> 结构关系。

例如：

- 与 Galaxy 核心越近，结构关联越强；
- 跨 Galaxy 的桥梁位于边缘或连接带；
- 不同 Galaxy 在 Overview 保持可辨识的空间分离。

距离来自实际 Anchor / Relation，而不是纯粹为了填满画布。

### 3.3 Clarity / Halo｜清晰度与星晕

主要表达：

> `resolution`｜我们对这个节点到底看清了多少。

例如：

```text
边缘稳定、结构清晰
→ 角色、能力或状态被较好解析

星晕扩散、边缘柔和
→ 真实存在，但独立程度、理解深度等仍未解析
```

重要：

模糊不是“差”。

它只表示：

> **系统还看不清。**

### 3.4 Relation Strength｜连线强度

主要表达：

> 关系证据有多稳定。

例如：

- 单次共同经历：弱；
- 多次重复共现：较强；
- 明确学习轨迹：有方向；
- 跨 Galaxy 桥梁：只在需要时突出。

Overview 不应该把所有边永久画出来，否则很快变成网络毛球。

默认可只显示少量最重要关系，其他在 Hover / Focus 时出现。

### 3.5 Motion｜动态

如果使用动态，主要表达：

> 当前活跃 / 正在形成 / 最近变化。

例如非常轻微的呼吸、轨迹或粒子流。

动态不应该表达“水平高低”。

长期稳定但暂时没在学习的知识，不应该因为没有动画就看起来“更差”。

---

## 4. Confidence 与 Resolution 不相同

这是视觉上非常容易混淆的一组概念。

例如：

```text
Rust 出现在课刻技术栈中
```

我们可以有：

```text
“Rust 属于这个人的项目经历”
confidence: high

“这个人能独立使用 Rust 开发”
resolution: low / unresolved
```

也就是说：

> **我们很确定它存在，但不知道它有多深。**

最终视觉必须允许这种组合存在。

这也是为什么不能简单使用：

```text
confidence 低 → 星变暗
confidence 高 → 星变亮
```

然后让用户把亮度误解成能力。

V0 可以优先把 Confidence 用作：

- 是否允许进入首层；
- 标签是否稳定；
- 解释面板中的明确说明；

而不是强行给它一个非常显眼的单一视觉通道。

---

## 5. State 不一定需要直接画在 Overview

Knowledge Model 有：

- Established；
- Developing；
- Observed；
- Unresolved。

但 Overview 不需要把它们做成四种明显的“等级皮肤”。

尤其不要形成：

```text
Established = 金色
Developing = 银色
Observed = 灰色
```

这种隐含排名。

更合理的是：

- `Unresolved` 通常不进入 Overview；
- `Observed` 可以明显存在，但解析视觉更柔和；
- `Developing` 可以通过近期轨迹 / 轻微动态体现“正在形成”；
- `Established` 可以稳定存在；
- 精确状态文字在 Hover / Detail 中说明。

---

## 6. 第一眼 → 聚焦 → 深入

建议最终交互至少分四个尺度。

### Scale 0 — Universe Overview｜宇宙轮廓

看到：

- Galaxy；
- 少量核心星；
- 整体重心；
- 大致结构。

目标：

> 远看像一幅属于这个人的作品。

### Scale 1 — Galaxy Focus｜星系聚焦

进入一个 Galaxy 后看到：

- Primary Nodes；
- 局部关系；
- Anchor；
- 第二层节点逐渐出现。

### Scale 2 — Node Focus｜节点聚焦

点击某颗星后看到：

- 状态；
- 当前解释；
- Exposure / Capability 区分；
- Resolution；
- 相关经历；
- 与其他节点的关系。

### Scale 3 — Evidence｜证据层

再深入可以回答：

> “你为什么这样认识我？”

展示：

- Source；
- Evidence；
- Attribution；
- Claim；
- Limits；
- 可校准区域。

因此：

> **远看是作品，近看是工具。**

并不是一句纯审美口号，而是信息架构本身。

---

## 7. Uncertainty 应该漂亮，而不是像报错

Knowledge Constellation 的一个核心特点就是允许 Unknown。

因此视觉上不应该把“未解析”做成：

- 红色警告；
- 禁用灰；
- 错误图标；
- 低分标签。

更合适的语言可能是：

- 星云；
- 柔和边缘；
- 未完全凝聚的光；
- 向外扩散但尚未稳定的结构。

它表达的是：

> **这里真实有东西，只是目前还没有完全显影。**

这也自然连接到 Micro Calibration：

> “校准这颗星”不是给它考试，而是让模糊区域更清楚。

---

## 8. 不要只依赖颜色传达关键状态

未来即使形成 Galaxy 配色，也不能只靠颜色区别：

- Established / Observed；
- 已解析 / 未解析；
- 当前 / 历史；
- 主关系 / 次关系。

原因包括：

- 可访问性；
- 深色 / 浅色主题；
- 截图和分享场景；
- 不同屏幕表现；
- 用户可能只注意“颜色好不好看”，而不是它的语义。

关键含义应该至少有第二种视觉或文字线索。

---

## 9. 稳定布局比每次“重新排最优”更重要

未来校准、更新资料或长期追踪后，星图会变化。

如果每次模型一更新就把所有节点重新随机布局，用户会失去空间记忆。

因此后续 Visual Model 应该考虑：

> **Layout Continuity｜布局连续性**

原则：

- 已存在的 Galaxy 尽量保持大致方位；
- 节点状态变化优先在原位置附近演化；
- 新 Galaxy 才开辟新的空间；
- 大规模重构应该让用户能看见“结构发生了变化”，而不是突然跳图。

这对于未来的 Longitudinal Constellation 尤其重要。

---

## 10. 当前最重要的视觉反例

### 反例 A

```text
Rust 技术复杂
→ 画成最大最亮的星
```

错误：复杂度不是个人代表性，也不是能力证据。

### 反例 B

```text
Observed
→ 自动缩小并变灰
```

错误：Observed 可能非常能代表用户，只是能力深度未知。

### 反例 C

```text
用户说“我很喜欢这个”
→ 能力星升级
```

错误：Identity Calibration 只能影响展示重心，不能污染能力 Claim。

### 反例 D

```text
所有 Evidence-backed Relation 永久显示
```

错误：信息正确但视觉不可读。

### 反例 E

```text
银河布局每次更新完全重排
```

错误：破坏用户对“这是我的宇宙”的空间记忆。

---

## 11. V0 视觉语义的最小目标

真正开始制作视觉原型之前，至少应该能够保证：

1. 大小不等于技能等级；
2. 模糊不等于能力差；
3. 位置来自个人结构而不是随机排版；
4. 第一眼只展示蒸馏后的少量信息；
5. 所有复杂判断都可以在第二层解释；
6. 校准可以让结构“显影”，而不是只让分数上下变化。

只有这些语义稳定之后，才值得认真进入视觉风格、动画和最终生成格式。
