# Milestone — Recognition Hardening: 10-user clean-room gate

> Status: candidate milestone checkpoint, pending final CI on this exact tree.

Recognition Hardening has now completed ten **distinct** public-GitHub users under the executable `kc.cleanroom.v2` protocol. The goal was not to make ten attractive summaries; it was to repeatedly let an isolated Runner form a person model, attack that output from outside, turn failures into generalized rules, rerun the same frozen sources, and then move to a structurally different unseen user.

## What the loop actually changed

### 1. The eval loop itself became executable

An early Simon run looked semantically plausible but did not match the active Pass schemas. That exposed a dangerous possibility: a manually assembled “Runner” could pass human review even though the real Harness would reject it.

`kc.cleanroom.v2` now requires canonical Pass A/B/C/D files and a replayable validator proof. `harness/verify_eval_case.py` and CI replay the active contracts. A pretty or plausible summary no longer counts as a test result.

### 2. Attribution survives compression

The devdanzin cases exposed that a node label can over-credit the human even when its hidden evidence boundary is accurate. `崩溃复现与最小化` bundled human re-reproduction with explicitly AI-assisted reducer work.

The generalized rule now requires node labels themselves to preserve meaningful attribution differences. Action-bearing Claims also carry explicit `attribution_evidence` so project behavior cannot silently borrow authorship from a separate observation.

### 3. AI/collaboration is not forced into Knowledge

AI assistance, collaboration, generation, templates and automation are normally provenance or working mode. They may become cross-cutting Motifs, but recurring AI use does not automatically deserve a Knowledge Star or its own Galaxy.

This preserved real human review, validation, authorization and judgment in devdanzin/tiangolo while refusing to relabel AI-generated implementation as unaided human work.

### 4. Chronology cannot be invented

A semantically plausible sequence is not a personal trajectory. `trajectory` Relations now require explicit source-grounded temporal basis: earlier/later evidence or a documented migration. Otherwise the system uses another supported relation type or leaves the relation absent.

### 5. Personal Anchors survive end-to-end

The first clean-room run exposed a cross-layer gap: Pass C could recognize real projects/experiences but Pass D had no formal place to preserve Project Anchors or Identity Presence. The Visual Model now carries accepted Anchors as provenance and keeps the exact input identity, so the personalized product surface no longer depends on a hand-written Scene repair.

### 6. Structure is allowed to stay small

Karpathy exposed a schema-induced semantic error: requiring two primary nodes per Galaxy encouraged unrelated real experiences to be merged under a synthetic umbrella. The contract now permits a truthful one-node Galaxy when no companion node is justified.

This generalized immediately to sparse/learning cases: Exercism, Fashion-MNIST, Zero-to-Hero, autoresearch, and finally a single starter JavaScript trace can remain separate rather than being padded into larger-looking clusters.

### 7. Learning and sparse evidence are first-class outputs

The heloa-net case confirms that a universe can meaningfully show learning/practice without upgrading it to mastery. The magdalenemc case confirms the stronger invariant: when the public evidence is almost empty, the correct product can be one quiet Knowledge Star, one Anchor and large unresolved space.

**More evidence may grow the universe; lack of evidence must never be visually disguised as richness.**

## Final gate invariants

The ten-user milestone is accepted only if the repository test gate on the same final commit confirms:

- all referenced v2 Runner artifacts still validate against current contracts;
- every milestone verdict is `PASS`;
- all milestone users are distinct;
- `critical_inflation == 0` for every accepted case;
- `material_warnings` is empty for every accepted case;
- Project Anchor / Identity handoff is intact;
- at least one strong independent-developer case passes the over-conservatism counter-test;
- the full existing Harness / Renderer test suite remains green.

## Remaining limitations

This is not proof that Recognition is solved.

1. All ten milestone users are grounded primarily in public GitHub evidence. Resumes, learning logs, portfolios and mixed private/public source bundles still need the same real-user gate.
2. In this environment most Runner/Auditor separation is **emulated**, not a truly separate-process blind Codex execution. A true independent-run gate remains valuable before stronger reliability claims.
3. Frozen sources are sampled rather than exhaustive. The system is being tested for truthful modeling under bounded evidence, not for reconstructing a complete biography.

## Milestone decision

If final CI is green, this is a meaningful Recognition checkpoint: the system has repeatedly survived materially different evidence shapes without a current critical inflation warning, while retaining strong evidence when it genuinely exists.

The next milestone should shift from repeatedly tuning these same GitHub cases to **end-to-end v0.1 generation from the real Harness**, plus a smaller second gate using truly independent Runner instances and non-GitHub source types.
