# v0.3 — Skill-first Harness Checkpoint

Knowledge Constellation now has a runnable semantic harness whose core invariant is explicit: **Codex is the semantic engine; Python is only orchestration and validation.**

## Pipeline

```text
Source
→ Codex Pass A: Evidence
→ Validator / Repair
→ Codex Pass B: Claims + Knowledge Nodes
→ Validator / Repair
→ Codex Pass C: Anchors + Relations + Galaxies + Distillation
→ Validator / Repair
→ Codex Pass D: Personal Visual Model
→ Validator / Repair
```

The harness must never create missing Evidence, Nodes, Claims, or Galaxies from keyword rules.

## Runtime isolation

Each semantic pass gets an isolated workspace containing only the root `SKILL.md`, orchestration contract, current prompt/schema, and the accepted upstream artifacts required by that pass. Test baselines, historical examples, unrelated fixtures, and prior expected answers are forbidden runtime inputs.

## Strong-claim gate

Strong implementation / independence / troubleshooting / transfer Claims require multiple independent evidence groups and multi-source provenance or explicit external validation. Repeating one self-authored source cannot manufacture independent corroboration.

## Current evaluation

The Tyr1onX public-source reconstruction recovered the accepted personal structure without reading the test-only gold baseline during semantic execution. Four additional public unseen-style cases were then used as bounded counterexample tests: a Tauri/Java proof-of-concept, a current React learner, an Android tooling learning journey, and a professional engineering resume.

This checkpoint does not claim universal accuracy for people. It establishes a repeatable, auditable Codex-in-the-loop Recognition protocol that can now be evaluated and improved without moving semantic judgment into a hidden rule engine.
