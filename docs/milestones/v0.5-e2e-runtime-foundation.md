# Milestone — v0.1 End-to-End Runtime Foundation

> Status: implementation checkpoint. The semantic engine remains Codex/Skill; Harness only orchestrates and validates.

This milestone connects the previously separate Recognition pipeline and accepted Renderer baseline into one reproducible path:

```text
Input Sources
  ↓
Pass A — Evidence
  ↓ validate / repair
Pass B — Model
  ↓ validate / repair
Pass C — Structure
  ↓ validate / repair
Pass D — Personal Visual Model
  ↓ validate / repair
Scene Composer
  ↓
kc.scene.v1
  ↓
Canonical Renderer Runtime
  ↓
interactive site/
```

## One orchestration entry

`harness/e2e.py` owns the host loop. It initializes the existing `pipeline.py`, repeatedly materializes isolated semantic workspaces, calls a caller-supplied semantic Runner, validates every candidate, consumes the existing repair budget, composes the final Scene, and builds a site directory.

The Runner boundary is explicit:

- the Runner process starts inside the isolated Pass workspace;
- it receives `KC_WORKSPACE`, `KC_TASK`, `KC_OUTPUT`, `KC_STAGE`, and `KC_MODE`;
- it must read `TASK.md`;
- it must write only the current Pass JSON to `KC_OUTPUT`;
- the Harness never fills in missing semantic content.

The command intentionally remains adapter-based instead of hard-coding one Codex CLI syntax. Different hosts can provide their own runner command without changing Recognition semantics.

```bash
python harness/e2e.py \
  --input input.json \
  --run runs/me \
  --dist dist/me \
  --runner-command "<your-codex-runner-wrapper>"
```

A runner command may use `{workspace}`, `{task}`, `{output}`, and `{stage}` placeholders.

## Scene Composer is deterministic, not semantic

`harness/compose_scene.py` converts accepted input, Evidence, Model, Structure and Personal Visual Model into `kc.scene.v1`.

It may perform renderer-owned mechanics: deterministic initial positions, visual size from representativeness/distillation role, primary/secondary layer mapping, relation distance/strength mapping, Project Anchor placement and stable seed-based layout.

It may **not** create or delete Knowledge Nodes, Relations or Galaxies; upgrade state/confidence/capability; or infer a skill from a dependency or keyword. Scene semantic validation therefore requires exact node, relation, Anchor, Galaxy and identity preservation from accepted upstream artifacts.

## Scene contract

`contracts/scene.schema.json` introduces `kc.scene.v1`. The Scene contains the data the Renderer actually needs: subject/identity, viewport, visual DNA, Knowledge Stars, evidence-backed Relations, Project Anchors, Galaxies and Motifs.

Default product nodes intentionally do not surface Recognition audit chrome such as confidence, unresolved dimensions or next-step suggestions. Evidence observations and source titles remain available for the secondary “查看依据” disclosure.

## Canonical runtime

`renderer/runtime.js` is the first reusable page runtime that consumes `scene.json` while using the accepted modules from `renderer/index.js`.

It reuses d3-force physics, point-light Knowledge Stars, adaptive overview visibility, global semantic zoom reveal, Identity Core physics/rendering, Identity Presence, Project Anchors/provenance links, product-surface detail presentation and Ambient Space.

Interaction invariants remain: spatial zoom alone reveals deeper stars; node inspection does not recenter; zoom-out peels detail/focus without recentering; Identity Core owns explicit return to overview; Project Anchor focus is a boost rather than a visibility gate.

## Site builder

`harness/build_site.py` creates:

```text
dist/<subject>/
  index.html
  scene.json
  manifest.json
  renderer/
    runtime.js
    index.js
    ...
```

Serve the generated directory over HTTP so module imports and `scene.json` behave consistently:

```bash
python -m http.server 8000 --directory dist/me
```

The v0.1 runtime currently loads D3 from a public CDN. Vendoring D3 is a packaging improvement, not a Recognition concern.

## Still separate

This checkpoint does not claim that a hosted “paste GitHub URL and wait” product already exists. Still separate are source-ingestion adapters, a concrete Codex-host runner wrapper for each execution environment, true separate-process blind Runner evaluation, hosted deployment/authentication, and static PNG/WebP export.

The next acceptance test is not another hand-authored HTML. It is a real source bundle run through the complete Harness into `scene.json` and the canonical runtime with no manual Scene repair.
