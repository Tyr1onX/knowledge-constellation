# v0.6 — Blind Codex visual validation

Status: **accepted checkpoint**

## What was tested

A fresh Codex task received only a natural one-line user request:

> 帮我安装并使用这个 Skill，根据我的 GitHub 主页生成一个属于我的个人知识星图。

The task installed the current repository Skill, used the public `Tyr1onX` GitHub profile as input, and produced a complete interactive Knowledge Constellation without a handcrafted SVG fallback.

## Accepted output

The accepted result used:

- `kc.scene.v1`
- canonical `renderer/runtime.js` and `renderer/shell.css`
- 29 Knowledge Nodes
- 29 Relations
- 6 Project Anchors
- 5 Galaxies
- deterministic scene seed `kc:Tyr1onX:github:2026-08-19:v1`

The generated page pinned renderer assets to commit `8822ea705722b125aa602c41e6e17be651bcf53b`, the first CI-green renderer consolidation checkpoint after the visual drift fix.

Human visual review accepted this version as materially closer to the intended Personal Universe baseline. The accepted Scene has therefore replaced the previous synthetic repository preview fixture.

## What this proves

This checkpoint demonstrates that a new Codex task can, from a normal user-style request, discover/install the Skill and reach a visually acceptable canonical interactive result while preserving the established Renderer language.

It does **not** prove pixel-identical rendering across browsers or future renderer revisions. A dedicated screenshot regression backend remains a later hardening step; until then, the accepted Scene plus renderer contract tests are the executable baseline.

## Product invariant locked here

Different people may have different Knowledge Nodes, Galaxies, Anchors, relative importance and bounded visual parameters.

They must not receive different-quality frontends. Generated pages and the repository preview must continue to share the same canonical Renderer.
