# 微校准｜Micro Calibration

Micro Calibration 的目标不是把用户拉进一次完整测评，而是：

> **在第一份画像已经生成之后，用极少量操作解决最影响整张图的几个不确定点。**

---

## 为什么用选择题

不同输入方式的用户成本差异很大：

```text
已有资料        成本最低
选择题          很低
短回答          中等
深度自述        较高
完整测评        很高
```

因此默认顺序应该是：

```text
Passive Evidence
已有资料直接建模
        ↓
生成第一张图
        ↓
Micro Calibration
少量选择题
        ↓
必要时才进入
Adaptive Calibration
```

用户不应该为了看到第一份结果先填一长串表格。

---

# 两种不同的校准不能混在一起

进一步研究后，需要把 Micro Calibration 明确拆成两条通道。

## A. Truth Calibration｜事实 / 归因校准

回答：

> **这件事实际上是怎么发生的？用户本人在里面做了什么？**

它可以更新：

- Attribution；
- Independence；
- Capability Claim；
- Resolution；
- 某些 Knowledge Node 的状态。

例如：

> 这些开源 PR 中，你通常更接近哪种参与方式？

这种答案会影响“实现、测试、调试到底能不能归因于本人”。

## B. Identity Calibration｜个人重要性校准

回答：

> **在这些已经真实存在的部分里，哪些更能代表你现在怎么看自己？**

例如第一张图生成后，可以低成本地问：

> **下面这些区域里，哪两块最像你现在真正投入的重心？**

```text
□ 开源参与与工程流转
□ 课刻与桌面产品
□ Web 基础补全
□ 都差不多
□ 都不太像
```

Identity Calibration 只能影响：

- `representativeness`；
- Galaxy / Node 的展示优先级；
- 视觉中心和信息预算。

它**不能**因为用户“很喜欢 Rust”就把 Rust 的能力 Claim 从 Observed 升级成 Established。

规则：

> **真实性校准改变我们“相信什么”；身份校准改变我们“优先展示什么”。**

这两条通道必须分离，否则产品满意度会反过来污染知识判断。

---

# 为什么需要 Identity Calibration

Passive Evidence 存在一个天然偏差：

> **证据密度不等于个人重要性。**

GitHub 会给代码、PR、CI 留下大量痕迹；

但有些对用户非常重要的知识、兴趣或能力可能几乎没有数字记录。

因此 Passive-only Distillation 最多得到：

> **Observable Representativeness｜从现有痕迹看起来有多能代表这个人。**

它不是用户主观意义上的最终重要性。

第一张图仍然应该直接生成，但后续可以用 1 个非常轻的选择题校准视觉重心。

---

# 核心原则：高信息增益｜High Information Gain

不要逐颗星询问：

```text
Rust 是不是你写的？
TypeScript 是不是你写的？
测试是不是你写的？
这个 PR 是不是你写的？
另一个 PR 呢？
```

应该问一个能够重新解释一整片区域的问题。

例如：

## 示例问题：开源贡献中的典型参与方式

> **你在这些开源 PR 中，通常更接近哪一种情况？**

A. 我主要提出想做什么，AI / 他人基本完成后续分析、实现和测试。

B. AI 完成较多，我会看结果、做一些修改，并负责真实测试或验收。

C. 我和 AI 共同完成，我能够阅读、理解并修改主要实现。

D. 主要由我自己分析和实现，AI 更多用于查资料、补测试或提高效率。

E. 不同 PR 差异很大 / 不好判断。

允许用户跳过。

---

## 为什么这一题价值高

它可能同时影响：

```text
开源技术能力
Git / PR 独立能力
测试与验证能力
调试能力
实现能力
AI Agent 使用方式
```

但不会删除“这些 PR 确实发生过”这一历史事实。

即：

```text
Activity / 活动事实    保持
Attribution / 角色归因  更新
Claim / 能力判断        更新
Node / 星体状态         重新计算
```

---

# 问卷设计规则

## 1. 第一份结果之前不强制问

Micro Calibration 默认出现在第一张图之后。

## 2. 一次只解决少数高价值模糊区

V0.2 建议最多 3～5 题。

不是因为 5 题能“完整认识一个人”，而是因为超过这个数量后用户成本会快速上升。

## 3. 选项描述行为，不让用户给自己打等级

避免：

> “你的 Rust 水平是？”

```text
初级 / 中级 / 高级 / 专家
```

更好：

> “如果现在不用 AI，让你修改这个项目里的一个小 Rust 功能，哪种描述更接近？”

```text
基本无法完成
能读一部分，需要大量帮助
有提示可以完成
大部分可以独立完成
这部分比较熟悉
不好判断
```

行为描述比抽象自评分更容易回答，也更不容易被“想让自己显得厉害”干扰。

## 4. 必须提供“不确定 / 不好判断”

强迫用户选一个看起来更厉害或更弱的答案，会制造假数据。

## 5. 一个答案不能直接升级成“掌握”

选择题仍然属于 `self_report`。

它可以显著改善 Attribution，但如果要确认更强的能力 Claim，仍然需要行为证据、外部证据或重复证据。

## 6. 身份偏好不能污染能力判断

用户可以说：

> “这个项目特别代表我。”

这可以让它在星图中更中心。

但不能因此推出：

> “用户对项目全部技术都更熟练。”

## 7. 能用排序 / 多选解决，就不要要求长文字

Identity Calibration 尤其适合：

- 选 1～2 个最重要主题；
- 对候选主题做简单排序；
- “更像我 / 不像我”；
- “现在重心 / 曾经重要 / 只是经历过”。

这些信息非常适合改善 Distillation，而不增加大量表达成本。

# 推荐的问题类型

## Truth Calibration

### Role Question｜角色归因

解决：这个成果里用户实际做了什么。

### Independence Question｜独立程度

解决：脱离 AI / 协作者以后还能做多少。

### Understanding Question｜理解程度

解决：用户是“见过 / 用过”，还是能解释主要机制。

### Recency Question｜近期状态

解决：历史能力是否仍然活跃。

## Identity Calibration

### Salience Question｜个人重要性

解决：哪个主题更能代表用户现在的重心。

### Identity Fit Question｜画像贴合度

解决：某个 Galaxy 是否“虽然证据很多，但其实不像我”。

### Phase Question｜阶段意义

解决：这是“现在正在形成的我”，还是“以前做过但已经离开的方向”。

V0.2 不需要全部询问，只选择当前模型信息增益最高的 1～3 类。

---

# 更新模型，而不是覆盖用户

校准后，系统不应该把第一张图判为“错误版本”。

更合理的表达是：

> **同一个人，不同解析度。**  
> Same person. Different resolution.

第一张图代表：

> 根据已有痕迹看到的你。

Truth Calibration 之后代表：

> 对实际参与方式认识得更清楚的你。

Identity Calibration 之后代表：

> 在不篡改事实判断的前提下，更接近你自己认为重要部分的你。

---

# 视觉反馈方向（后续）

如果一个回答让某项技术的实现归因降低，但让 AI Agent 使用证据增强，视觉上应该真实体现这种重新分配，而不是简单“扣分”。

例如：

```text
Rust 独立实现      变弱 / 保持朦胧
测试能力            视回答重新判断
AI Agent 实践        变得更明确
开源参与            保持
```

而 Identity Calibration 可能产生另一种变化：

```text
能力 Claim           不变
Galaxy 结构           大体不变
视觉中心             调整
节点大小 / 距离       调整
首屏信息预算          重新分配
```

这样用户看到的是“画像更像自己”，而不是“通过选择喜欢什么来修改技能分数”。
