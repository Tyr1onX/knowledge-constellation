# Distillation｜蒸馏与首屏信息预算

> 结构模型回答“哪些东西属于同一个主题”；蒸馏模型回答“第一眼到底该让人看见什么”。

Knowledge Constellation 不能把所有已知节点同时铺出来。

如果把 Rust、TypeScript、Tauri、HTTP、CORS、JWT、DOM、SQLite、CAS、CI、OCR、Windows DPI……全部放在第一层，结果即使数据正确，也会变成一团技术关键词。

因此需要一层独立的 **Distillation（蒸馏）**。

---

## 1. 最重要的分离：代表性 ≠ 能力强弱

一个节点是否应该显眼，首先取决于：

> **它有多大程度能够解释“这个人现在是谁”。**

而不是：

> 这个人的该项能力有多强。

例如 Rust 可能长期存在于一个核心项目中，因此具有较高代表性；但公开证据仍不足以确认独立开发能力。

所以可以出现：

```text
Rust
代表性：高
能力解析度：低
证据置信度：中/低
```

视觉上它可以“存在感明显”，但不能让用户误解成“Rust 水平很高”。

---

## 2. 不使用单一 Skill Score

V0 不计算一个总分决定节点大小。

内部至少区分以下维度：

### `representativeness`｜代表性

这个节点是否能解释这个人的重要经历和当前方向。

### `confidence`｜证据置信度

系统对“这个节点确实属于这个人”有多确定。

### `resolution`｜解析度

系统对这个节点的具体状态了解得有多清楚，例如是否知道独立程度、理解深度和实际角色。

### `structural_role`｜结构作用

节点是：

- 核心节点；
- 普通成员；
- 跨星系桥梁；
- 外围经历；
- 第二层细节。

### `recency`｜近期性

该节点是否仍在当前阶段反复出现。

这些信号可以影响展示，但不能被压成一个伪精确的“83 分”。

---

## 3. 代表性从哪里来

V0 使用相对判断 `high / medium / low`，主要看以下信号。

### 3.1 Recurrence｜重复出现

是否在多个时间点、多个活动中反复出现。

一次性出现的技术，即使很高级，也通常不应成为大节点。

### 3.2 Anchor Breadth｜锚点跨度

是否连接多个独立 Anchor。

例如某种实践同时出现在：

- 个人项目；
- 开源贡献；
- 学习记录。

那么它往往比只存在于单个文件中的概念更能解释这个人。

### 3.3 Continuity｜连续性

是短暂出现，还是持续数周、数月或更久。

### 3.4 Explanatory Power｜解释力

如果移除这个节点，我们对这个人的整体理解是否明显下降？

### 3.5 Personal Specificity｜个人特异性

它是否帮助区别这个人与“一个随机的软件学习者”？

例如单独的 `JavaScript` 很常见；

但“课刻与桌面产品”或一种持续的 AI Agent 工作方式可能更具有个人识别度。

### 3.6 Redundancy｜冗余

一个节点的信息是否已经被另一个更高层节点很好地表达。

例如首屏可能显示：

```text
Web / 网络基础
```

而把 HTTP、Cookie、CORS、缓存等放进第二层。

不是因为这些知识不重要，而是首屏不需要重复表达同一结构。

---

## 4. 四个蒸馏测试

在决定一个节点是否进入第一层时，可以依次问：

### Test A — 删除测试 / Removal Test

> 如果把这个节点从第一眼删除，这张图还像这个人吗？

如果几乎没有变化，它通常不需要进入首层。

### Test B — 压缩测试 / Compression Test

> 这个节点能否同时解释多条证据、多段经历或多个相邻节点？

解释力越强，越适合成为首层节点或 Galaxy 核心。

### Test C — 替换测试 / Substitution Test

> 如果把它换成一个泛化标签，会不会失去明显的个人特征？

如果 `软件开发` 可以无损替换它，那么标签可能太泛。

### Test D — 诚实测试 / Honesty Test

> 把它放得这么显眼，会不会让正常用户自然理解成比证据更强的能力声明？

如果会，优先调整视觉编码；必要时降到第二层。

这个测试非常重要：

**展示的语义不能比知识模型本身更激进。**

---

## 5. 首屏不是完整知识图谱

建议把最终体验分成多层。

### Layer 0 — Silhouette｜轮廓

用户第一眼看到：

- 少量 Galaxy；
- 每个 Galaxy 的名称；
- 极少数最有代表性的核心星。

目标：3 秒内能形成“这个人大概是什么结构”的感觉。

### Layer 1 — Primary Constellation｜主要星图

展示每个 Galaxy 中最能代表这个人的节点，以及少量跨星系关系。

V0 可以使用一个**软预算**：

- 通常 2–5 个 Galaxy；
- 第一层总计大约 6–12 个主要节点；
- 每个 Galaxy 通常 1–4 个主要节点。

这不是硬性限制。如果证据明显支持更少，就宁愿更少。

### Layer 2 — Local Detail｜局部细节

缩放、悬停或点击之后再看到：

- 具体技术；
- 子知识；
- 一次性经历；
- 较弱关系；
- 学习中的细粒度主题。

### Layer 3 — Evidence｜证据与解释

进一步进入节点，可以看到：

- 为什么它存在；
- 来自哪些 Source；
- 哪些 Claim 支持它；
- Attribution 状态；
- 系统还不知道什么；
- 是否可以校准。

这对应产品原则：

> **远看是作品，近看是工具。**

---

## 6. 默认隐藏哪些东西

以下内容通常不应该直接进入首层。

### 6.1 一次性高级概念

例如某一个 PR 涉及：

- CAS；
- SQLite WAL；
- 特定并发 bug。

如果它们没有在更多经历中重复出现，就更适合作为局部细节。

### 6.2 同义或高度冗余节点

例如首层不需要同时展示：

```text
HTTP
HTTP/2
HTTP/3
QUIC
缓存
CDN
Cookie
CORS
```

如果当前要表达的是一条“Web 基础学习线”，可以由更高层节点概括。

### 6.3 纯工具痕迹

某个工具只因为构建链或依赖出现，不应自动得到第一层位置。

### 6.4 无法解释其个人意义的节点

即使证据证明用户接触过，如果它不能帮助解释当前结构，也可以保留在模型中但不展示。

---

## 7. Unknown 不等于隐藏

一个非常重要的例外：

> **解析度低的节点仍然可以很有代表性。**

例如一个人持续两年围绕 Blender 做作品，但无法判断其高级建模能力。

Blender 仍然应该非常显眼。

因此不应该：

```text
confidence 低
→ 自动缩小
```

更合理的是把不同含义映射给不同视觉属性：

```text
视觉存在感 / 大小
→ 代表性

亮度 / 稳定感
→ 证据稳定程度

清晰度 / 边缘
→ 解析度

距离
→ 与 Galaxy 核心的结构关联
```

最终视觉语言还需要单独研究，但语义必须从现在开始保持分离。

---

## 8. Galaxy 也需要蒸馏

不是所有 Motif 都应该成为 Galaxy。

一个 Galaxy 候选进入首屏前也应该问：

1. 它是否解释了足够多的经历？
2. 它与其他 Galaxy 是否真正不同？
3. 名称是否具有个人特征？
4. 如果移除它，人物轮廓是否明显变弱？
5. 它是否只是某个更大主题的细分？

相似 Galaxy 应优先合并。

例如：

```text
Web 基础
浏览器基础
JavaScript 学习
```

在当前阶段可能更适合合并为：

```text
Web 基础补全
```

等未来其中某一条发展出独立轨迹，再自然分裂。

---

## 9. Distillation 是有损压缩，但必须可逆解释

首屏本质上是一种有损压缩。

它会主动隐藏信息。

但必须满足：

> **展示可以省略证据，不能篡改证据。**

也就是说，任何首屏星星都应该能够向下追溯：

```text
Galaxy
↓
Motif
↓
Knowledge Node
↓
Claim
↓
Evidence
↓
Source
```

这样用户看到一个漂亮结果时，随时可以问：

> “为什么你觉得这个东西属于我？”

系统必须答得出来。

## 10. 对 Tyr1onX Passive 样本的首轮蒸馏

只基于当前公开 Passive Evidence，比较合理的第一眼不是把所有节点全部列出。

### Galaxy A — 开源参与与工程流转

首层候选：

- 开源参与；
- GitHub / PR 工作流；
- 测试与验证（解析度较低）。

第二层：

- 并发；
- SQLite；
- 具体 PR 涉及的技术问题。

理由：并发和 SQLite 当前主要来自少数具体贡献，代表性不足以成为第一眼核心。

### Galaxy B — 课刻与桌面产品

首层候选：

- 产品迭代；
- Tauri；
- Rust 或 TypeScript 中少量最能表达项目环境的节点。

这里 Rust / TypeScript 即使显眼，也必须保持“高 Exposure、低 Capability Resolution”的视觉语义。

第二层：

- Windows 桌面细节；
- OCR；
- Excel 解析；
- 更具体的项目实现技术。

### Galaxy C — Web 基础补全

首层候选：

- Web / 网络基础；
- 浏览器渲染；
- JavaScript / DOM。

第二层：

- HTTP 细分主题；
- Cookie / Session / JWT；
- CORS；
- Cache / CDN；
- script / defer / async 等。

Passive-only 阶段暂时不建立 `AI-assisted Development` Galaxy，因为公开证据不足以支持它。

---

## 11. 蒸馏的成功标准

一个好的第一层应该让用户觉得：

> “它没有把我知道的所有词都扔出来，但留下来的东西确实很像我。”

而不是：

> “它把我的 README 和简历做成了一个词云。”

因此 Distillation 的最终目标是：

> **用尽可能少的可见结构，保留尽可能多的个人解释力。**
